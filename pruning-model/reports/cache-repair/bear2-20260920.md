# Cache reuse with real Bear-2 compression

**Selective repair reused 66.7% of compressed-history KV states and reduced
median cache transition time from 587 ms to 305 ms. Fresh rebuilding and
selective repair both answered 7/12 factual questions correctly, versus 8/12
with original history. This is approximate reuse, not lossless cache repair.**

This run used The Token Company's actual Bear-2 API outputs with the existing
local Qwen2.5-1.5B-Instruct repair prototype. It does not modify TTC's hosted
service or demonstrate access to another hosted model's internal cache.

## Setup

- Bear-2, aggressiveness **0.2**, official Python SDK **0.5.1**: 20 successful
  requests covering 14 histories; no failures, retries, or fallback compressor.
- Only historical session text was sent to Bear-2. Final questions, reference
  answers, and evidence labels were excluded. Returned text was used unchanged.
- Qwen/Qwen2.5-1.5B-Instruct, revision
  `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`, FP16, Mac MPS, PyTorch 2.14.0,
  Transformers 4.57.6; greedy decoding, maximum 128 new tokens.
- Fourteen previously inspected public LongMemEval oracle-history cases:
  twelve factual and two preference questions. This is a development diagnostic,
  not a new holdout or the standard full-history benchmark.
- Five cache strategies, each with a shape-specific warmup and three timed
  repetitions; randomized arm order, seed 17. All 70 strategy outputs completed.

Qwen history length fell from **53,671 to 46,530 tokens: 13.3% reduction**.
The unchanged final questions add 705 tokens. TTC's own counts were 54,010 input
and 45,940 output tokens across the session-only requests; its accounting differs
from Qwen's full rendered histories.

## Results

| Strategy | Compressed-history KV states reused | Median cache transition | Answers identical to fresh rebuild | Factual correctness |
|---|---:|---:|---:|---:|
| Fresh compressed rebuild | 0% | 587.4 ms | 14/14 | 7/12 |
| Exact common-prefix reuse | 2.97% | 658.3 ms | 14/14 | 7/12 |
| Selective repair, minimum 10% budget | 66.69% | 305.1 ms | 8/14 | 7/12 |
| Selective repair, minimum 25% budget | 65.31% | 332.7 ms | 8/14 | 7/12 |
| Full repair, correctness control | 0% | 772.9 ms | 14/14 | 7/12 |

The minimum-10% strategy reduced the displayed median by **48.1%**. The ratio
of summed paired transition times was **1.68x**, or 40.6% less aggregate time.
These are different statistics. Selective repair beat fresh rebuilding and exact
prefix reuse on all 14 cases in this run. These comparisons are within this run;
absolute timings should not be compared directly with earlier experiments.

The requested fraction is a minimum, not a guarantee of 90% reuse. Bear-2's text
output lacks source deletion offsets in the SDK response used here. The adapter
infers monotone matching character blocks and then checks Qwen token boundaries.
Unmatched tokens, ambiguous offsets, and changed joins require rebuilding.
They account for **33.3%** of compressed-history tokens. Conservative diff
alignment can also miss reusable source text; this is not a lower bound imposed
by Bear-2 itself. The 10% and 25% strategies selected exactly the same positions
in 11/14 cases because mandatory rebuilding already exceeded both budgets.

Reuse describes cached token states, not total FLOPs or memory reduction.
Surviving keys still need positional rotation and tensors must be copied.
All strategies finish with the same shortened prompt length. Original and new
caches coexist during transition; peak memory was not measured.

## Answer quality

Exact prefix reuse and full repair matched fresh rebuilding's first-token logits
and generated token sequences on all 14 cases. Selective repair matched both the
first token and complete output on 8/14. Median first-token KL divergence was
0.1058 at the 10% minimum and 0.0838 at the 25% minimum. This is distribution
drift, even though factual correctness happened to stay equal.

Every compressed arm got the same seven factual items right: Sacramento
abstention, mother's grocery method, Alex meeting count, Arati Prabhakar,
guitar practice duration, moving duration, and device purchase order. The
original-history control also answered the Manolo García question correctly.

**Bear-2 retained the Manolo García evidence.** The compressed text still names
him and states his support for unity between Catalonia and Spain, but Qwen with
a freshly rebuilt cache incorrectly abstained. That observed regression cannot
be attributed to cache repair or deletion of the answer. It illustrates the
distinction between retaining a fact and this small target model successfully
using the edited text.

Repair changed two already-wrong numeric answers: fresh rebuilding said 25%
of packed shoes were worn while selective repair said 50% (reference: 40%);
fresh rebuilding said three travel days while selective repair said four days
in each city (reference: eleven or twelve total). Equal correctness scores do
not mean equivalent outputs.

The two preference cases were reviewed qualitatively and excluded from the
factual denominator. For the reunion question, fresh rebuilding abstained while
repair offered generic advice; neither used the requested personal memories.
For the evening question, fresh rebuilding returned a list truncated at 128
tokens, while repair returned only a meditation suggestion. Neither respected
the before-9:30 preference. Shorter output is not automatically better quality.

Review was performed by the Codex agent against saved outputs, public references,
and inspected source evidence. It is not independent human review or the official
LongMemEval judge. Twelve factual questions cannot establish accuracy equivalence.

The earlier ModernBERT experiment scored 4/12 with compressed history, but it
removed about 81% of history tokens versus Bear-2's 13.3% here. This is not a
comparison at matched compression ratios and does not isolate compressor quality.

## Latency scope

Cache transition includes building or repairing KV and processing the final
query. Selective repair also includes recorded alignment and retokenization
preparation (median 64.6 ms). Original prefill, model loading, compression API
time, and answer generation are excluded from the transition column.

Bear-2 took a median **292.7 ms per case**, summing its session requests, and
4.36 seconds across all 20 requests. Adding API time to transition time gives
these medians, calculated per case before aggregation:

| Strategy | Compression API + cache transition | API + transition + decode |
|---|---:|---:|
| Fresh rebuild | 926.7 ms | 1,213.0 ms |
| Exact prefix reuse | 1,007.9 ms | 1,309.9 ms |
| Selective repair, minimum 10% | 671.5 ms | 999.9 ms |
| Selective repair, minimum 25% | 699.1 ms | 996.3 ms |

These totals sum recorded stages rather than measure a single live request.
Decode was measured once per arm and outputs differ (264 generated tokens
across fresh-rebuild cases versus 174 for selective repair), so the last column
is not a controlled equal-output latency comparison.

Continuing the original warm cache without compression took a median **52.6 ms
for the incoming query**, or 366.7 ms including decode. These are single samples
excluding original prefill and the isolation copy. Compression plus repair did
not beat simply continuing that warm cache in this experiment. Its potential
benefit is shortening future context and reducing future work; repeated-turn
amortization was not tested.

## Implementation and reproducibility

The [Bear-2 preparation adapter](../../src/pruning_model/bear2_cache_inputs.py)
journals API results and writes exact compressed text plus source alignment.
The [benchmark](../../src/pruning_model/cache_repair_benchmark.py) accepts
`--bear2-run`, validates preparation artifact hashes, and runs the same repair
API and baselines against those outputs. New tests cover history-only requests,
exact API settings/output preservation, alignment consistency, no final-question
leakage, and failed-call handling. **All 59 pruning-project tests passed.**

Artifact verification confirmed 70 unique case/strategy rows, three timing
samples each, 14 original controls, unchanged preparation artifacts, and matching
executed-source snapshot hashes. Local artifacts, under Git-ignored `runs/`:

- `runs/bear2-inputs-20260920/`: API receipts, exact outputs, cases, and manifest.
- `runs/cache-repair-bear2-20260920/`: raw answers and timings, source snapshot,
  `quality_review.json` with case-by-case judgments, and `verified_report.json`.

The [README](../../README.md#use-bear-2-compression) gives commands to prepare
new Bear-2 outputs and repeat the benchmark. Local cache tests can reuse the
completed preparation without making more compression calls.

This result supports approximate cache reuse with real Bear-2 output. It does
not establish lossless inference, repeated-compaction stability, production
throughput, peak-memory savings, or hosted-provider cache/billing behavior.
